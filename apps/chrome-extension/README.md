# Finfold for Chrome 1.1.4 — Reply drafts pilot

Manifest V3 side-panel extension that turns only the page a user actively chooses into native drafts for X, LinkedIn, Xiaohongshu, and Reddit.

## Local verification

```bash
npm install
npm test
npm run package
```

Load `dist/` from `chrome://extensions` with Developer mode enabled. The production ZIP is written to `release/finfold-chrome-extension-v1.1.4.zip`; its audit rejects unexpected permissions, development hosts, remote/dynamic code, source maps, obvious secrets, and incorrectly sized icons.

The API origin is intentionally fixed to `https://www.finfold.app`. For an unpacked integration test, use a production-compatible staging hostname rather than adding local or wildcard host permissions to the release manifest.

## Privacy boundary

- No page is read until the user opens Finfold or invokes its context menu. Autopilot polls only while the side panel is open; closing the panel stops everything.
- Page extraction is local until Generate is pressed and the first-send disclosure is accepted.
- Post mode excludes images, form values, cookies, and browsing history. Reply mode reads only the comments and post text of the user's own Xiaohongshu/LinkedIn post while the panel is open.
- Replies are typed and sent only after the user confirms each one — or, with Autopilot explicitly switched on, automatically for comments on the current page, capped at 30 per day, paused after 3 consecutive failures, with needs-context drafts never auto-sent. Nothing is ever sent in the background or on a schedule while the panel is closed.
- When the reply box cannot be found in the DOM, one one-off screenshot may be sent to Finfold's vision model to locate it (used once, never stored); the user can switch this off in the panel.
- Refresh tokens are restricted to trusted extension contexts; access tokens use session storage.


## Reply assistant

The Reply tab automates the full reply loop on the user's own posts for LinkedIn and Xiaohongshu:

1. **Capture** — opening the panel injects a packaged function into the active tab (the pilot manifest's `host_permissions` for xiaohongshu.com / linkedin.com plus `scripting`; the store build keeps `activeTab` only because it ships the reply assistant as stubs) that reads the visible comments and post text locally; the user picks a comment or pastes one.
2. **Generate** — the reply is generated by the real Finfold service with saved brand context and the existing 3-Credit billing, exactly as before.
3. **Confirm & send** — after the user presses Confirm & send, the extension locates that comment's reply box in the page DOM, types the reply (native value setter for React fields, `insertText` for contenteditable) and clicks send.
4. **Visual fallback** — if the DOM walk fails and the user allows it, the panel sends one screenshot to `POST /api/extension/v1/reply-automation/locate`; a vision model (GLM vision, fail-closed when no vision provider is configured) returns the reply box and send button as normalized coordinates, which the extension clicks.
5. **Copy fallback** — if automation still fails, the reply is copied automatically for a manual paste.

There is no anonymous reply generation, no fake fallback, and no comment monitoring or send action without an explicit per-comment confirmation. The backend must enable the authenticated private pilot first.

## Autopilot

Autopilot (自动模式) is an opt-in switch in the reply panel that removes the per-reply clicks. While the panel is open on a Xiaohongshu or LinkedIn post page, it:

1. Re-captures the page on tab switches, navigation and an 8-second poll.
2. Works through unhandled comments one at a time — generate (3 Credits, same idempotent request pipeline), a short human-paced pause, then the same tiered send (DOM → vision). Each comment is processed at most once per week (`finfoldAutoLedger` in local storage keys by platform + author + text).
3. Never auto-sends a needs_context draft — those are logged for the user to answer.
4. Stops itself: 3 consecutive generation failures, 30 generations in a local day, insufficient Credits, or the server's daily reply limit. Each pause is shown in the panel with its reason and clears when the user switches Autopilot on again.
5. Defers to the user: while a manually typed comment is in the box, nothing automatic starts.

The switch state persists (`finfoldAutoPilot`), the daily ledger persists (`finfoldAutoLedger`), and everything stops the moment the panel closes.

The server-side pilot is gated by environment flags on the deployed Finfold instance (`FINFOLD_EXTENSION_REPLY_DRAFTS_ENABLED`, `FINFOLD_EXTENSION_REPLY_PILOT_MODE`); installing this package alone does not enable it.

## App design alignment (1.1.4)

The side panel uses Finfold App's Editorial / Signal light and dark tokens, Geist font, and canonical app icons. `prebuild` and `predev` copy those assets from the repository through `scripts/sync-design.mjs`. Logos are embedded through Vite asset imports and work without a runtime network request or root-relative icon path. The ZIP audit verifies both embedded logos, the font and its license. Theme choice is saved locally in Chrome.

The static visual proofs in `artifacts/reply-assistant/preview*.html` show both modes and themes. They are explicitly labelled previews, with no account connection or model generation. The post-mode proof uses the public workbench's copy as visual-review material.

## Interface language

Use EN / 中文 in the header. The choice is stored locally and updates both creation modes without resetting inputs, edited replies or a pending request. Reply output language is a separate control.
